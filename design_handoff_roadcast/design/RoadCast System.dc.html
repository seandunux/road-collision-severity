RDesign rationale

Information hierarchy

Predict follows the task: configure, calculate, compare, understand. Inputs are grouped under three headings (Road, Environment, Time) separated by rules instead of boxes, so the form reads as three short lists. The result card is the only bordered surface on the page, which makes it the obvious place to look after calculating.

  • Inside the card, the order is: probability, status, the two reference numbers, then the scale that shows all three together.
  • Plain-language influences come first. The SHAP waterfall and log-odds sit behind “View technical explanation”.
  • Data and Model insights read top to bottom: the conclusion first, then one chart per question, each with its own takeaway.

Probabilities, thresholds and baselines

The old design used a 112px glowing number and a HIGH RISK tag, which made a screening threshold look like a danger line. The redesign keeps three separate quantities separate:

  • Estimate: the number at 72px, labelled in full.
  • Alert threshold: a status chip worded “Above/Below alert threshold”, with a note that it is a precision–recall trade-off.
  • Dataset baseline: the 23.3% average, so people can tell “above threshold” apart from “above typical”.

The live threshold (22.5%) sits just under the baseline, so an estimate like 22.9% is above one and below the other. The comparison pair and the scale make that visible instead of hiding it.

Colour

White page, near-black text, cool greys, and one blue (#3A55D0, 6.2:1 on white). Blue marks positive influence, the current estimate and the one bar each chart’s takeaway names. Everything else is neutral. Negative influence is a mid grey, which is lighter than the blue so the two separate in greyscale too.

  • Amber appears only for unrecorded inputs, and red only for real errors.
  • Muted text is #687080 rather than the suggested #6F7785, which measures 4.3:1 on #F7F8FA and would fail AA.
  • Form-control edges are #8A919D (3.2:1) to meet the 3:1 non-text contrast rule. #C8CED7 is kept for decoration only.

Typography

Inter at 15px/24px for body text, 14px for labels and 13px as the floor. Headings use weight 600 with slight negative tracking. Tabular figures keep percentages aligned in tables, bars and the comparison pair. The big number shrinks from 72px on desktop to 52px on mobile and stays the largest element on screen.

Recording effects

“Information unavailable” behaves like a recording gap, not a condition. In the data, collisions with an unrecorded road type are serious or fatal at 8.6%, against 25.0% for single carriageways. So the design separates unrecorded values in menus, styles them differently in the form (dashed, grey, badge, hint), hatches them in charts, tags them in explanations, and raises an amber note when they affect a result.

Accessibility

  • Every text pairing meets WCAG AA. Control edges and chart marks meet 3:1.
  • Status, direction and reference lines all have a shape, line style or word as well as colour.
  • Real buttons, labels and range inputs, with visible 2px focus rings. Help icons have accessible names.
  • Each chart has a one-sentence text alternative and a data-table toggle. The result region is aria-live, so a new estimate is announced.
  • Spinners only animate when reduced motion isn’t requested. Layouts use flexible widths so 200% zoom reflows rather than clips.

Building it in Streamlit

  • Theme in .streamlit/config.toml: base “light”, primaryColor #3A55D0, backgroundColor #FFFFFF, secondaryBackgroundColor #F7F8FA, textColor #16181D, font Inter.
  • st.columns([0.37, 0.63]) for inputs and result. The result card is st.container(border=True). Groups are st.markdown headings with an hr.
  • Stale state: compare the current widget values with the ones stored alongside the result in st.session_state.
  • The comparison scale, status chip and explanation rows are small HTML blocks via st.markdown. Charts are Plotly using the spec above.
  • About the data uses st.dialog. Technical explanation, More road details and How to read these charts use st.expander.
  • Road surface is a new input. The app currently fixes it to Dry, so it needs exposing from the existing road_surface_conditions feature.

Dynamic values

Every estimate, contribution and difference shown is an example. The threshold and model metrics come from the model bundle (save_model_data["threshold"] and ["metrics"]), and dataset rates should be computed from the data at load time and cached. Only the feature-importance ranking was copied from the saved SHAP chart, and it should be recomputed from shap_sample.pkl.
